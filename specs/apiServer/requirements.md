# 要件（apiServer）

全体の要件は [../requirements.md](../requirements.md)。

## cookie セッション認証

| ID | 要求 | 全体要求 |
|---|---|---|
| A1 | `/download` と `/schedule` で、cookie プロファイル名（`auth_profile`）を指定できる | R1 |
| A2 | 解析（probe）の時点で、ログインが必要な状態を検知し、レスポンスでログインが必要であることを返す | R4 |
| A3 | ログインが必要な旨のレスポンスは、原因（未指定・未登録・失効）と、再ログイン用画面の URL を含む | R4, R10 |
| A4 | ログインが必要なことは、サーバの不調として扱わない（プロセスを再起動しない） | R4 |
| A5 | 予約実行（`/download/scheduled`）でログインが必要になった予約は、失われず残る | R4 |
| A6 | プロファイルの名前と状態を確認できる。cookie の中身は返さない | R6, R8 |
| A7 | ユーザ指定のオプションで、認証情報・cookie を指定させない | R3, R8 |
| A8 | cookie・認証情報を扱う操作（登録・ログイン）を API に持たない | R7 |

### 制約

- 外部（Cloudflare Tunnel）に公開されるため、cookie の登録や取得の入口にならないこと。

## cookie セッション認証（Phase 4: プロファイルの自動選択）

| ID | 要求 | 全体要求 |
|---|---|---|
| A9 | `auth_profile` を省略したとき、URL のサイトに対応するプロファイル（プリセット・履歴）があり、その cookie が有効なら、それを使う。明示指定があればそちらを優先する | R13 |
| A10 | 自動選択できるプロファイルの cookie が未保存・失効中でも、ログイン不要のコンテンツは従来どおり取得できる（cookie を使わずに解析する） | R13 |
| A11 | 自動選択の対象サイトでログインが必要になったら、そのプロファイルの再ログイン用 URL を返す | R4, R10 |
