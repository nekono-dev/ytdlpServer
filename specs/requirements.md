# 要件（全体）

yt-dlp をキュー経由で実行する API サーバ。ここでは、複数アプリにまたがる要求だけを書く。アプリ固有の要求は各アプリの `requirements.md` を参照する。

| アプリ | 役割 | 要件 |
|---|---|---|
| apiServer | リクエスト受付・解析・ジョブ投入 | [apiServer/requirements.md](apiServer/requirements.md) |
| workerServer | ジョブ実行 | [workerServer/requirements.md](workerServer/requirements.md) |
| browserServer | ブラウザでのログインと cookie 取得（新規） | [browserServer/requirements.md](browserServer/requirements.md) |

## cookie セッション認証

### 背景

一部の動画サイトで、yt-dlp の `--username` / `--password` によるログインができなくなった。
`--cookies` などセッションを使う方法が必要になった。

### 目的

ログインが必要な動画を、ユーザがブラウザでログインしたセッションを使って取得できるようにする。

### 要求

| ID | 要求 | 対象 |
|---|---|---|
| R1 | リクエストで cookie プロファイル名を指定して、ログインが必要な動画を取得できる | api, worker |
| R2 | ユーザがブラウザ上でログインする操作だけで、cookie が取得・保存される。cookies.txt の書き出しや配置を必要としない | browser |
| R3 | ユーザ名・パスワードをこのシステムに渡さず、保存もしない | 全て |
| R4 | API へのリクエスト時に、ログインが必要な状態（cookie 未指定・未登録・失効）を検知し、レスポンスでログインが必要であることを返す | api |
| R5 | キューに積んだ後で cookie が失効した場合も検知し、ジョブに記録する。cookie が更新されるまで自動リトライしない | worker |
| R6 | cookie を更新すれば、サーバを再起動せずに使える状態へ戻る | 全て |
| R7 | ログイン済みセッションの取得・登録は、外部公開される API では行わない | api, browser |
| R8 | cookie の値・認証情報を、ログ・Redis・API レスポンスに出さない | 全て |
| R9 | サイトごとのログイン画面の自動操作を実装せず、複数のサイトに対応できる | browser |
| R10 | ログインが必要な旨のレスポンスから、再ログイン用の画面へ辿れる | api, browser |

### 制約

- 利用は LAN 内を前提とし、ブラウザ操作画面には認証を設けない。
- Cloudflare Tunnel で外部へ公開されるのは API のみ。
- CAPTCHA・2 段階認証は自動突破しない（人がブラウザで操作する）。
- ログイン画面の表示・入力は人が行うため、サイトのログイン手順の変更に影響されない。

### 非機能要件

- ブラウザは、ログイン操作中だけ動く。待機中の負荷を小さく保つ。
- ログイン操作は同時に 1 件とし、一定時間で自動終了する。
- 取得した cookie は、パスワードと同等に扱う（ファイル権限、コミット防止）。

### スコープ外

- ユーザ名・パスワードによる自動ログイン。
- CAPTCHA の自動突破、外部の解答サービスの利用。
- 外部への通知（Webhook など）。ログイン要求はレスポンスで返す。
