# API サーバ 要件定義書

## 1. 目的

動画の URL を受け付け、yt-dlp で解析してジョブに分解し、キューへ積む HTTP API を提供する。ログインが必要な動画は、cookie のプロファイルで取得でき、ログインが必要な状態を原因つきで利用者へ返せる。

## 2. スコープ

### 2.1 対象

- ダウンロード要求、予約要求、予約実行、再実行要求の受付。
- 認証関連オプションの拒否と、cookie プロファイルの選択。
- ログイン要求の応答と、再ログイン用 URL の案内。
- ワーカー起動役への通知と、yt-dlp の新版確認の依頼。

### 2.2 対象外

- cookie の登録とログイン操作。
- ジョブの実行とワーカーの起動。
- yt-dlp の更新そのもの。

## 3. 前提

- 前提: cookie-store — プロファイルの状態判定、自動選択、再ログイン用 URL を共有するため

## 4. 機能要件

- FR-1: ダウンロード要求を受け、URL を yt-dlp で解析してジョブへ分解し、一意な ID を付けてキューへ積み、受理を返す。
- FR-2: 予約要求を保存し、予約実行の指示で取り出して、ダウンロード要求と同じ手順で処理する。
- FR-3: ダウンロード要求と予約要求で cookie プロファイル名を指定でき、指定はジョブと予約に引き継がれる。
- FR-4: 認証関連のオプションと不正なプロファイル名は、400 で拒否する。
- FR-5: 指定プロファイルが未保存か失効中なら解析せずに 401 を返し、解析中のログイン要求も 401 とプロファイルの失効記録にする。
- FR-6: 401 の応答は、原因（未指定・未登録・失効）、プロファイル名、再ログイン用 URL を含み、プロセスを再起動しない。
- FR-7: プロファイル名を省略したとき、URL に対応するプロファイルの cookie が有効なら使い、無効なら cookie なしで解析する。
- FR-8: 予約実行でログイン要求になった予約は、失われずに予約キューの先頭へ戻る。
- FR-9: ジョブを積んだときにワーカー起動役へ通知し、解析がログイン要求以外で失敗したら 400 と新版確認の依頼を返す。
- FR-10: 予約実行でログイン要求以外の失敗をした予約は、失敗用の予約リストへ退避し、残りの予約の処理を続ける。
- FR-11: 再実行要求は、失敗ジョブの失敗回数を 0 に戻して通知し、ワーカーが取得済みのジョブを再作成しない。
- FR-12: プロファイル一覧要求は、名前・状態・再ログイン用 URL を返し、cookie の中身を返さない。

## 5. 非機能要件

- NFR-1: yt-dlp の更新を目的とした API プロセスの再起動は 0 回とする。
- NFR-2: 認証関連オプションの拒否応答に含める値は 0 件とする。

## 6. 受け入れ条件

- AC-1 (FR-1): 解析に成功した要求では、ジョブがキューに積まれ、受理の応答が 200 で返る。
- AC-2 (FR-1): 同じ URL を2回投入すると、ジョブ ID の異なる2件のジョブが積まれる。
- AC-3 (FR-2): 予約を保存して予約実行を指示すると、予約が取り出され、プロファイル名を保ったままジョブが積まれる。
- AC-4 (FR-3): プロファイル名つきの要求では、積まれたジョブと保存された予約にプロファイル名が含まれる。
- AC-5 (FR-4): 認証関連のオプションまたは規則に合わないプロファイル名を含む要求は、400 になる。
- AC-6 (FR-5): 失効中のプロファイルを指定すると解析せずに 401 になり、cookie を置き直した後は解析に進む。
- AC-7 (FR-5): 解析がログイン要求を返すと、401 になり、そのプロファイルが失効として記録される。
- AC-8 (FR-6): プロファイル名を省略した要求で解析がログイン要求を返すと、未指定を示す原因と再ログイン用 URL つきの 401 になる。
- AC-9 (FR-6): 指定プロファイルが未保存のとき、未登録を示す原因の 401 になる。
- AC-10 (FR-7): 対応するプロファイルの cookie が有効な URL では、そのプロファイルで解析される。
- AC-11 (FR-7): 対応するプロファイルが未保存か失効中なら cookie なしで解析され、ログイン要求のときは候補が案内される。
- AC-12 (FR-8): 予約実行でログイン要求になった予約は、予約キューの先頭に戻り、401 がそのまま返る。
- AC-13 (FR-9): ジョブを積むと通知が発行され、通知の発行が失敗しても受理が返る。
- AC-14 (FR-9): ログイン要求以外の解析失敗では、400 と新版確認の通知が返り、プロセスは終了しない。
- AC-15 (FR-10): 失敗した予約が失敗用の予約リストへ移り、後続の予約が処理され、応答に処理件数と失敗件数が含まれる。
- AC-16 (FR-11): 再実行要求で失敗ジョブの失敗回数が 0 になり、通知が発行される。
- AC-17 (FR-11): 再実行要求の途中でワーカーがジョブを取得した場合、そのジョブは再作成されない。
- AC-18 (FR-12): プロファイル一覧の各行に再ログイン用 URL が含まれ、cookie の中身は含まれない。
- AC-19 (NFR-1): 解析の失敗後も、プロセスを終了させる処理が呼ばれない。
- AC-20 (NFR-2): 認証関連オプションの拒否応答にはオプション名だけが含まれ、値は含まれない。
