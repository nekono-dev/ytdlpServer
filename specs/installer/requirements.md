# ytdlpServer インストーラ 要件定義書

## 1. 目的

Ubuntu 24.04 のベアメタルおよび LXC コンテナへ、ytdlpServer の全構成を1行の取得実行コマンドで導入できるようにする。導入後は常設コマンドで更新・撤去・設定変更・状態確認を行える。ブランチやタグへの push ごとに、そのコミットに固定した頒布物を自動生成して公開する。

## 2. スコープ

### 2.1 対象

- 導入、更新、撤去、状態表示のサブコマンド。
- 設定ファイルの生成、検証、既存値の保持。
- 任意コンポーネントの導入と有効・無効の切り替え。
- 頒布物の生成と、GitHub への自動公開。

### 2.2 対象外

- Docker による導入。
- Ubuntu 24.04 以外の OS への導入。
- 動画ファイルの削除。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: install は、Ubuntu 24.04 の root 実行で API・dispatcher・Redis・pot-provider を導入して起動し、再実行しても同じ結果になる。
- FR-2: 設定ファイルは権限 600 で生成し、値の優先順位は 引数指定、環境変数、既存の設定ファイル、既定値の順とする。
- FR-3: 宣言のないキー、必須キーの欠落、禁則文字を含む値は、システムを何も変更せずに中止する。
- FR-4: 数値、列挙、動画の保存先の位置、Cloudflare トークンの有無の誤りは、パッケージ導入の前に検出して中止する。
- FR-5: update は、既存の設定値を保持したまま新しいキーを追記し、常設コマンドでは導入時の REF の最新へ、頒布物ではそのコミットへ揃える。
- FR-6: install と update で任意コンポーネントの有効・無効を指定すると、導入、または停止と撤去に切り替わる。
- FR-7: uninstall は、アプリ本体・サービス・常設コマンド・取得先を削除し、設定・cookie・Redis のデータ・動画を残す。
- FR-8: uninstall に purge を付けると、設定・cookie・Redis のデータ・導入メタ情報を削除し、動画は削除しない。
- FR-9: status は、導入先・REF・コミット・取得元・更新日時を表示し、未導入のときは未導入と表示する。
- FR-10: Redis と pot-provider は 127.0.0.1 のみで待ち受け、各サービスは起動順の依存を持ち、異常終了後に自動で再起動する。
- FR-11: ブランチ push では頒布物をアーティファクトと Pre-release へ、タグ push では Release へ公開し、手動実行でも同じ処理を行う。
- FR-12: 頒布物は埋め込まれたコミットのソースだけを取得し、取得結果がそのコミットと一致しなければ実行を中止する。

## 5. 非機能要件

- NFR-1: 2回目以降の install は、導入済みの pot-provider と Redis Insight を再ビルドせず、120秒以内に完了する。
- NFR-2: 設定ファイルの権限は 600、cookie の保存先の権限は 700 にする。
- NFR-3: インストーラのシェルスクリプトは、shellcheck の警告レベルで指摘 0 件にする。
- NFR-4: Redis の Web UI を除く標準構成の install は、メモリ 4096MB の空の Ubuntu 24.04 コンテナで 900秒以内に完了する。

## 6. 受け入れ条件

- AC-1 (FR-1): 空の Ubuntu 24.04 コンテナで install すると、API が応答し、install の再実行後も同じ設定と状態になる。
- AC-2 (FR-2): 既存の設定ファイルを手編集して install を再実行すると、編集値が残り、引数指定の値だけが上書きされる。
- AC-3 (FR-3): 宣言のないキーの引数指定、またはシングルクォートを含む値では、設定ファイルもサービスも変更されずに終了コード 1 で終わる。
- AC-4 (FR-4): ワーカー数に数値以外を指定すると、パッケージ導入の前に終了コード 1 で中止される。
- AC-5 (FR-4): 動画の保存先に設定の保存先の配下を指定すると、パッケージ導入の前に終了コード 1 で中止される。
- AC-6 (FR-5): スキーマにキーを追加したコミットへ update すると、新キーが追記され、既存キーの値は変わらない。
- AC-7 (FR-6): update で nginx を有効にすると 443 番ポートで応答し、無効にすると nginx の設定が撤去されて 443 番ポートが閉じる。
- AC-8 (FR-6): Redis Insight の導入条件を満たさない環境では、redis-commander で Web UI が起動する。
- AC-9 (FR-7): uninstall の後は、サービスと常設コマンドと取得先が存在せず、設定と cookie と動画が残る。
- AC-10 (FR-8): uninstall に purge を付けた後は、設定と cookie と Redis のデータが存在せず、動画は残る。
- AC-11 (FR-9): 導入済みの環境では5項目が表示され、未導入の環境では未導入と表示される。
- AC-12 (FR-10): 導入後の Redis と pot-provider は 127.0.0.1 にのみ待ち受け、API を強制終了すると5秒以内に再起動する。
- AC-13 (FR-11): 公開用ワークフローは、ブランチ push・タグ push・手動実行の各トリガーを持ち、各ジョブが公開先ごとに分かれている。
- AC-14 (FR-12): 埋め込まれたコミットと異なるソースを取得させると、頒布物が 0 以外の終了コードで中止する。
- AC-15 (NFR-1): 導入済みの環境で install を再実行すると、ビルド処理が走らずに120秒以内に終わる。
- AC-16 (NFR-2): 導入後の設定ファイルの権限は 600、cookie の保存先の権限は 700 である。
- AC-17 (NFR-3): shellcheck を警告レベルで実行すると、指摘が 0 件である。
- AC-18 (NFR-4): メモリ 4096MB の空の Ubuntu 24.04 コンテナで、標準構成の install が900秒以内に完了する。
