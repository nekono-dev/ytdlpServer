# yt-dlp バイナリ選択 要件定義書

## 1. 目的

yt-dlp の導入先が glibc の Linux でも musl の Linux でも、その環境で動く公式バイナリを自動で選んで導入できるようにする。Docker の Alpine イメージと Ubuntu への直接導入が、同じ更新処理を共有できる。

## 2. スコープ

### 2.1 対象

- 実行環境の libc とアーキテクチャに応じた、取得するバイナリの選択。

### 2.2 対象外

- バイナリの取得先の変更。
- チェックサム検証の方式の変更。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: glibc の環境では、x86_64 なら yt-dlp_linux、aarch64 なら yt-dlp_linux_aarch64 を選ぶ。
- FR-2: musl の環境では、x86_64 なら yt-dlp_musllinux、aarch64 なら yt-dlp_musllinux_aarch64 を選ぶ。
- FR-3: 未対応のアーキテクチャでは、実行時エラーで中止する。

## 5. 非機能要件

- なし

## 6. 受け入れ条件

- AC-1 (FR-1): glibc の x86_64 と aarch64 で、それぞれ対応するバイナリ名が返る。
- AC-2 (FR-2): musl の x86_64 と aarch64 で、それぞれ対応するバイナリ名が返る。
- AC-3 (FR-3): 未対応のアーキテクチャを与えると、実行時エラーになる。
