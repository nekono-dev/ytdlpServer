# ワーカー 要件定義書

## 1. 目的

キューのジョブまたはリトライ対象のジョブを1件取得して yt-dlp で実行し、結果を記録して終了するワーカーを提供する。停止や異常終了があっても、ジョブが失われず、同じジョブを複数のワーカーが同時に実行しない。

## 2. スコープ

### 2.1 対象

- ジョブの取得、実行、結果の記録。
- リースによる生存の表明と、所有者の確認。
- 停止の指示への対応。
- cookie を使った実行と、ログイン要求による失敗の記録。

### 2.2 対象外

- ワーカーの起動と、中断されたジョブの回収。
- yt-dlp の更新。
- ジョブの受付と解析。

## 3. 前提

- 前提: cookie-store — cookie の受け渡しと、ログイン要求の判定を共有するため

## 4. 機能要件

- FR-1: ワーカーは起動すると、リトライ対象を優先してキューより先に1件取得し、処理して終了し、対象が無ければ待たずに終了する。
- FR-2: リトライ対象の取得は原子的な名前変更で行い、先に他のワーカーが取得していたら取得に失敗する。
- FR-3: キューからの取り出しは処理中の記録へ原子的に移して行い、解析できないジョブは退避する。
- FR-4: 生存を示すリースを、起動から終了まで一定間隔で更新し続ける。
- FR-5: 完了・失敗・中断の記録は、そのジョブの所有者が自分であるときだけ行う。
- FR-6: 停止の指示を受けたら yt-dlp を停止し、失敗回数を消費せずに再実行の対象にして終了する。
- FR-7: リースを更新できない状態がリースの有効期間にわたって続いたら、自ら実行を中止する。
- FR-8: ジョブの保存先とファイル名で yt-dlp を実行し、再実行でも同じ保存先とファイル名を使う。
- FR-9: YouTube の抽出引数に、クライアント指定の既定値を補い、ユーザが明示した指定は変えない。
- FR-10: プロファイルつきのジョブは cookie の一時コピーで実行し、失敗でも書き戻し、ログのコマンドでは cookie の指定値を伏せる。
- FR-11: ログイン要求で失敗したジョブには、理由の区分、再ログイン用 URL を記録し、プロファイルを失効にする。
- FR-12: ログイン要求以外の失敗は、失敗回数を1増やし、前回の理由の区分を残さずに記録する。

## 5. 非機能要件

- NFR-1: 停止の指示から yt-dlp の強制終了までの猶予は、既定で 20 秒とする。
- NFR-2: リースの更新間隔は既定で 10 秒、有効期間は既定で 60 秒とする。
- NFR-3: cookie の値は、ログと Redis のジョブ記録のいずれにも 0 件出力する。

## 6. 受け入れ条件

- AC-1 (FR-1): ジョブが無いと待たずに終了し、リトライ対象があればキューより先に処理される。
- AC-2 (FR-2): 同じリトライ対象を取得できるのは1つのワーカーだけで、上限に達したものと、ログイン待ちのものは対象外になる。
- AC-3 (FR-3): キューの取り出しは処理中の記録を経由して処理中のジョブの記録になり、空のキューでは何も返らない。
- AC-4 (FR-3): 解析できないジョブは退避用のキューへ移り、ワーカーは終了コード 0 で終了する。
- AC-5 (FR-4): リースは取得・更新・解放ができ、解放後は生存と判定されない。
- AC-6 (FR-5): 所有者が別のワーカーになっていたジョブには、結果が書き込まれない。
- AC-7 (FR-6): 停止の指示の後は、実行を始めずに再実行の対象になり、失敗回数が増えない。
- AC-8 (FR-6): 実行中の停止の指示で、yt-dlp に停止が送られ、猶予を過ぎると強制終了される。
- AC-9 (FR-7): リースの更新が失敗し続けると、停止の指示と同じ扱いで実行が中止される。
- AC-10 (FR-8): 保存先とファイル名が出力先に反映され、ファイル名が空ならジョブの識別子が使われる。
- AC-11 (FR-8): 失敗したジョブを再実行しても、保存先とファイル名が変わらない。
- AC-12 (FR-9): YouTube の指定が無ければ既定値が加わり、ユーザが明示したクライアント指定は変更されない。
- AC-13 (FR-10): プロファイルつきの実行は cookie の一時コピーを使い、失敗しても更新が書き戻され、ログの値が伏せられる。
- AC-14 (FR-10): 未保存のプロファイルのジョブは、実行せずにログイン要求として失敗する。
- AC-15 (FR-11): ログイン要求の失敗では、理由の区分と再ログイン用 URL が記録され、プロファイルが失効になる。
- AC-16 (FR-11): プロファイルの無いジョブでは、URL に対応するプロファイルの再ログイン用 URL が記録される。
- AC-17 (FR-12): ログイン要求以外の失敗では、失敗回数が増え、理由の区分が空になる。
- AC-18 (NFR-1): 停止の猶予の既定値が 20 秒である。
- AC-19 (NFR-2): リースの更新間隔の既定値が 10 秒、有効期間の既定値が 60 秒である。
- AC-20 (NFR-3): ログ用のコマンドと失敗の記録に、cookie の値が含まれない。
