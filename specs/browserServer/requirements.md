# 要件（browserServer）

新規のアプリケーション。全体の要件は [../requirements.md](../requirements.md)。

## cookie セッション認証（Phase 2）

| ID | 要求 | 全体要求 |
|---|---|---|
| B1 | ユーザが、自分のブラウザから、ログイン用のブラウザを操作してログインできる（クライアントソフトの追加インストールは不要） | R2 |
| B2 | ログインが終わったら、ユーザの保存操作で、ログイン済みの cookie がプロファイル名で自動保存される。cookies.txt の書き出し・配置は不要 | R2 |
| B3 | 任意のサイトで使える。サイトごとの実装を要さず、開始 URL を指定するだけでよい | R9 |
| B4 | CAPTCHA・2 段階認証・SMS 認証は、ユーザがブラウザ上で操作して通せる | R2 |
| B5 | 保存する cookie は、開始 URL のサイトのものに限る | R8 |
| B6 | 保存や取り消しの後、ログインのセッション情報（ブラウザのプロファイル）を残さない | R8 |
| B7 | ログイン操作は同時に 1 件。一定時間で自動終了する | 非機能 |
| B8 | 待機中は、ブラウザを起動しない | 非機能 |
| B9 | 保存できたか（保存した cookie の数）、または保存できなかった理由をユーザへ返す | R2 |
| B10 | API の再ログイン用 URL（`login_url`）から開いたとき、プロファイル名と開始 URL が入力済みになる | R10 |
| B11 | パスワードや cookie を、ログ・画面・API のレスポンスに出さない | R8 |

### 制約

- LAN 内利用を前提とし、認証は設けない。外部（Cloudflare Tunnel）へ公開しない。
- ログインの操作は人が行う。自動入力・自動突破はしない。
- 複数のドメインにまたがってログインするサイト（Google と YouTube など）は、Phase 2 の対象外（Phase 3 で扱う）。

### スコープ外（Phase 2）

- プロファイルの削除・名前変更。
- ログイン完了の自動検知（保存はユーザの操作で行う）。
- Alpine インストーラ（Docker 無し構成）への組み込み。
