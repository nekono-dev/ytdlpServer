# 要件（browserServer）

新規のアプリケーション。全体の要件は [../requirements.md](../requirements.md)。

## cookie セッション認証（Phase 2）

| ID | 要求 | 全体要求 |
|---|---|---|
| B1 | ユーザが、自分のブラウザから、ログイン用のブラウザを操作してログインできる（クライアントソフトの追加インストールは不要） | R2 |
| B2 | ログインが終わったら、ユーザの保存操作で、ログイン済みの cookie がプロファイル名で自動保存される。cookies.txt の書き出し・配置は不要 | R2 |
| B3 | 任意のサイトで使える。サイトごとの実装を要さず、開始 URL を指定するだけでよい | R9 |
| B4 | CAPTCHA・2 段階認証・SMS 認証は、ユーザがブラウザ上で操作して通せる | R2 |
| B5 | 保存する cookie は、開始 URL のサイトのものに限る | R8 |
| B6 | 保存や取り消しの後、ログインのセッション情報（ブラウザのプロファイル）を残さない | R8 |
| B7 | ログイン操作は同時に 1 件。一定時間で自動終了する | 非機能 |
| B8 | 待機中は、ブラウザを起動しない | 非機能 |
| B9 | 保存できたか（保存した cookie の数）、または保存できなかった理由をユーザへ返す | R2 |
| B10 | API の再ログイン用 URL（`login_url`）から開いたとき、プロファイル名と開始 URL が入力済みになる | R10 |
| B11 | パスワードや cookie を、ログ・画面・API のレスポンスに出さない | R8 |

### 制約

- LAN 内利用を前提とし、認証は設けない。外部（Cloudflare Tunnel）へ公開しない。
- ログインの操作は人が行う。自動入力・自動突破はしない。
- 複数のドメインにまたがってログインするサイト（Google と YouTube など）は、Phase 2 の対象外（Phase 4 のプリセットで扱う）。

### スコープ外（Phase 2）

- プロファイルの削除・名前変更。
- ログイン完了の自動検知（保存はユーザの操作で行う）。
- Alpine インストーラ（Docker 無し構成）への組み込み。

## cookie セッション認証（Phase 3: 画面配信方式への置き換え）

noVNC（リモートデスクトップ）はスマートフォンで操作しにくいため、ブラウザの画面を操作画面へ直接配信し、タッチ・キーボードを送る方式に置き換える。

| ID | 要求 | 全体要求 |
|---|---|---|
| B12 | 端末の表示領域の大きさで、ログイン先のページが表示される（スマートフォンではスマートフォン向けの表示） | R11 |
| B13 | タップ・スクロール・ピンチなどのタッチ操作が、そのままログイン先のページに届く。PC ではマウスとホイールで操作できる | R11 |
| B14 | ページの入力欄をタップすると、端末のキーボード（日本語入力を含む）で入力できる。パスワードマネージャ等からの貼り付けもできる | R11 |
| B15 | 新しいタブ・ポップアップ（外部アカウントでのログイン等）に、表示が追従する。戻る・再読み込みができる | R11 |
| B16 | CAPTCHA（Cloudflare Turnstile 等）を、人の操作で通せる | R2 |
| B17 | 画面配信以外のポート（VNC 等）を LAN へ公開しない | 非機能 |

## cookie セッション認証（Phase 4: プロファイルのプリセットと履歴）

| ID | 要求 | 全体要求 |
|---|---|---|
| B18 | 操作画面では、プロファイルをプルダウンから選ぶ。選択肢は、プリセットと、ユーザが追加した履歴 | R12 |
| B19 | プリセット（YouTube・ニコニコ・Instagram・X・Bilibili）は、ログイン用の URL と、保存対象のドメインを設定ファイルに持つ。YouTube のように複数ドメインの cookie が必要なサイトにも対応する | R12 |
| B20 | 新しいサイトは、プロファイル名と開始 URL を入力して使う。保存に成功したら、その組を履歴として覚える | R12 |
| B21 | 履歴は削除できる（編集はできない）。削除すると、そのプロファイルの cookie も削除する。プリセットは削除できない | R12 |
| B22 | プルダウンに、各プロファイルの cookie の保存状況（未保存・保存日時）を表示する | R12 |
| B23 | 再ログイン用 URL（`login_url`）から開いたとき、該当するプロファイルが選ばれた状態になる。未知のサイトなら、新しいサイトの入力欄に URL が入った状態になる | R10 |
