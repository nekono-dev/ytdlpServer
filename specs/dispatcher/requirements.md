# ワーカー起動役 要件定義書

## 1. 目的

ジョブがあるときだけワーカーを起動する常駐プロセスを提供する。待機中の負荷と外部通信を最小に保ち、ワーカーが中断されても、ジョブが失われたり処理中のまま残ったりしないよう回収する。Docker Compose と Docker 無しの Linux の両方で、同じ設定名で動く。

## 2. スコープ

### 2.1 対象

- キューとリトライ対象の監視、ワーカーの起動数の決定、起動と停止。
- 通知と定期スキャンによる検知、起動失敗時の間隔調整。
- 中断されたジョブの回収。
- 新版確認の依頼の中継と、設定の読み込み。

### 2.2 対象外

- ジョブの実行と、ジョブの状態の更新。
- yt-dlp の取得と検証。
- ジョブの内容の解釈。

## 3. 前提

- 前提: cookie-store — ログイン待ちのジョブを起動の対象から外すため
- 前提: ytdlp-updater — 新版の確認を同じプロセスで実行するため

## 4. 機能要件

- FR-1: キューのジョブとリトライ対象のジョブがあるときだけワーカーを起動し、無い間は起動しない。
- FR-2: ログイン待ちのジョブは、cookie が更新されて有効に戻るまで、起動の対象に数えない。
- FR-3: 通知の受信と定期スキャンの両方で対象の発生を検知し、通知を取りこぼしても、スキャン間隔以内に検知する。
- FR-4: 起動する数は、対象のジョブ数と空きの小さい方にし、実行中の数は自身の再起動の後も数え直せる。
- FR-5: ワーカーが処理を始めずに異常終了を続けたときは、起動の間隔を倍々に空け、正常終了で元に戻す。
- FR-6: リースが切れたワーカーの処理中ジョブと取り出し中の記録を回収し、失敗回数を消費して再実行の対象にする。
- FR-7: ワーカーの終了を検知したら直ちに再評価し、所有者の記録が無い古い処理中ジョブは指定時間の経過後に回収する。
- FR-8: Docker Compose では、docker-socket-proxy 経由で、ワーカーの作成・起動・停止・一覧・終了イベントの購読だけを行う。
- FR-9: Docker 無しの環境では、ワーカーを子プロセスとして起動し、ワーカー用の常駐サービスを持たない。
- FR-10: 停止の指示を受けたら、起動したワーカーに停止を指示してから終了する。
- FR-11: 新版確認の通知を受けたら、新版確認の依頼として中継する。
- FR-12: 設定は環境変数で変更でき、旧名の同時実行数も最大数の別名として受け付ける。

## 5. 非機能要件

- NFR-1: 定期スキャンの既定間隔は 30 秒、ワーカーのリースの既定有効期間は 60 秒とする。
- NFR-2: 起動失敗時の間隔は 5 秒から始めて倍にし、上限を 60 秒とする。
- NFR-3: 待機中の通信先は Redis と docker-socket-proxy に限り、ジョブの URL とオプションの読み取りは 0 回とする。

## 6. 受け入れ条件

- AC-1 (FR-1): 対象のジョブが無いとワーカーは起動されず、ジョブがあると起動される。
- AC-2 (FR-2): ログイン待ちのジョブは対象に数えられず、cookie が更新されると数えられる。
- AC-3 (FR-3): 通知の受信で起床し、通知が無くても定期スキャンで対象が検知される。
- AC-4 (FR-4): 起動する数は、対象の数と空きの小さい方になり、空きが0のときは起動されない。
- AC-5 (FR-4): 実行中のワーカーを、ラベルによる一覧から数え直せる。
- AC-6 (FR-5): 異常終了が続くと起動の間隔が延び、正常終了で0に戻る。
- AC-7 (FR-6): リースの無いワーカーの処理中ジョブが、失敗回数を消費して再実行の対象に回収される。
- AC-8 (FR-6): リースが生きているワーカーのジョブは、回収されない。
- AC-9 (FR-6): 取り出し中の記録は、処理中の記録があれば要素だけを消し、無ければキューの先頭に戻る。
- AC-10 (FR-7): 所有者の記録が無い処理中ジョブは、指定時間を過ぎたものだけが回収される。
- AC-11 (FR-7): ワーカーの終了が検知され、終了コードが取得できる。
- AC-12 (FR-8): ワーカーのコンテナは、自身と同じイメージ・マウント・ネットワークで、固定のコマンドと目印のラベルつきで作られる。
- AC-13 (FR-9): 子プロセスの起動と、実行中の数の取得ができる。
- AC-14 (FR-10): 終了時に、起動したワーカーすべてに停止が指示される。
- AC-15 (FR-11): 新版確認の通知で強制確認の要求が立ち、通常の通知では立たない。
- AC-16 (FR-12): 旧名の同時実行数は最大数の別名として読まれ、新名が優先される。
- AC-17 (NFR-1): 設定の既定値が、スキャン間隔 30 秒とリースの有効期間 60 秒である。
- AC-18 (NFR-2): 起動失敗の間隔が5秒始まりで倍になり、上限が60秒である。
- AC-19 (NFR-3): 起動役のコードにジョブの JSON を読む処理が無く、作成するコンテナのコマンドが固定である。
